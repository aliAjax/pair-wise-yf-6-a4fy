# 家庭维修事项

端口规划：`5114`

```bash
npm install
npm run dev
```

第二版：多人协作闭环——维修事项 → 师傅报价 → 预算审批 → 付款记录。

- **多设备协作**：每个浏览器标签页即一台设备（可改名），通过共享操作日志同步；再开一个标签页即可模拟另一台设备。
- **离线合并**：断网时的修改进入本机离线队列并即时可见（标记"待同步"），回网后整个队列作为一个批次，按「设备号 + 批次序号」与其他设备的批次确定性合并，各端重放结果一致；同步日志面板可见每个批次。
- **冲突裁定**：两台设备基于同一版本修改同一事项时，后到的版本进入冲突区，两版都保留，由户主选择"保留当前版本"或"采用对方版本"。
- **报价联动审批**：报价一变更，先前批准的预算即失效并留痕，事项退回待审批，需户主重新批准后才能付款。
- **付款重试**：付款失败后保留付款现场（金额/方式/备注/失败原因），重试沿用同一 attemptKey，只更新原付款记录（尝试次数累加），不会生成第二条；已成功的记录不会被重复重试变更。
- **费用明细按角色显示**：户主看全部（报价/已批预算/已付/付款明细与合计）；成员看报价、审批状态与已付合计；师傅只看报价与报价状态。

演示要点：顶栏可切换角色与在线状态、勾选"模拟付款失败"；"重置演示数据"可还原种子数据。

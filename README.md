# 家庭维修事项

端口规划：`5114`

```bash
npm install
npm run dev
```

第一版闭环：记录维修问题、按状态查看、更新处理状态、统计未完成预计费用，支持照片链接并使用 localStorage 保存数据。

第二版在同一页面里把「维修事项 → 师傅报价 → 付款记录」接成一条多人协作流程，用切换设备 + 断网/回网模拟多人离线协作：

- **离线进度按设备号 + 批次序号合并**：每台设备的离线修改进入本机待同步队列（批次号按设备递增），回网后点「同步回网」按 `设备号:批次号` 幂等合并，同一批次重复同步不会重复应用。
- **两台设备同时改同一事项 → 保留两版等户主裁定**：同步时若发现某事项的共享版本已被另一台设备改过（版本号不一致），则把「当前共享版 A」与「离线提交版 B」都保留下来，顶部出现冲突横幅，户主在弹窗里对比差异后选择采用哪一版。
- **报价一变，预算失效、事项退回待审批**：师傅或户主改了报价后，若此前已批准预算，则该预算标记为「已失效」（划线展示），事项状态自动退回「待审批」，需户主重新批准。
- **付款失败保留现场，重试只生成一条记录**：每个事项只保留一条付款记录；付款失败后记录保留失败原因与尝试次数，点「重试付款」在原记录上累加尝试次数并更新状态，不会新增第二条。
- **费用明细按角色显示**：户主可见报价、批准预算与付款金额；家人/师傅可见报价与付款状态，但预算与付款金额显示为 `•••`（户主可见）。

## 演示步骤

1. 顶部「当前设备」切到「家人平板」，点「○ 离线」断网，修改某事项（如改备注/状态），左侧「待同步批次」出现一条。
2. 再切到「师傅手机」，保持离线，修改**同一事项**，又出现一条待同步。
3. 点「● 在线」回网，点「同步回网」→ 弹出「版本冲突」裁定弹窗，对比 A/B 两版后选择采用哪版。
4. 户主视角下改一下某事项的报价，若该事项已批准预算，会看到「预算已失效」徽章并退回待审批。
5. 勾上「模拟付款失败」，点「发起付款」→ 记录「支付失败」；取消勾选后点「重试付款」→ 同一条记录变为「已支付」，尝试次数 +1，记录数不变。

```bash
node verify.mjs   # 合并幂等 / 冲突两版 / 预算联动 / 付款重试 共 25 项
node smoke.mjs    # 渲染冒烟 共 18 项
```

核心协作逻辑在 `src/store.js`（纯函数，可直接 node 测试），界面在 `src/ui.js`，接线在 `src/main.js`，配置在 `src/config.js`。
